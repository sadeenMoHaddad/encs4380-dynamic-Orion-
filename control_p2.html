P2: A slow sensor in the loop

The controller never sees the real output y. It only sees what the sensor reports, m, and a slow sensor reports late. The controller keeps pushing after the real output has already arrived, so the overshoot grows with the sensor time constant τs, until the loop oscillates.

Why it happens

The sensor is a first-order lag, m' = (y − m)/τs. It adds phase lag to the loop: the error e = r − m still looks large when y has already reached r, so the integral keeps winding up and the output overshoots. The larger τs is compared with the loop's own speed, the less phase margin is left, and past a certain point the loop oscillates. Metrics above are measured on the true output; the controller only ever sees m.

Rule of thumb: keep the sensor at least 5–10 times faster than the closed loop you want.
